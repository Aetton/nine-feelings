# Девять чувств / Nine Feelings

Локальный дневник эмоций для Android 8+. Девять настраиваемых кнопок, виджет, история, комментарии и статистика. Без аккаунтов, рекламы, аналитики, сетевых разрешений и внешних библиотек приложения. Интерфейс пока на русском языке. MIT License.

Версия **0.4.1** — кандидат первого публичного релиза. Результаты проверок и оставшиеся ограничения перечислены в [RELEASE_READINESS.md](RELEASE_READINESS.md). Публичные исходники: https://github.com/Aetton/nine-feelings. Приложение ещё не включено в каталог F-Droid.

## Использование

- Добавьте виджет 2×2 или 3×3 из приложения либо из меню виджетов Android.
- Нажатие сразу сохраняет эмоцию. Карточка подтверждения показывается 2,8 секунды; нажатие на неё открывает именно эту запись для комментария. Заголовок виджета открывает историю.
- Нажмите отметку в истории для комментария, исправления эмоции или удаления с подтверждением.
- ⚙ открывает редактирование названия, значка и цвета девяти ячеек. Замена кнопки не меняет прошлые записи. Статистика отдельно показывает значения из прежнего набора.
- Статистика доступна за 7 календарных дней, 30 дней или всё время. День и время определяются часовым поясом телефона. История загружается по 50 записей на страницу.
- В настройках доступны резервная копия, восстановление, информация о конфиденциальности и лицензия.

## Данные и резервные копии

Дневник находится в закрытом хранилище Android. Автоматические облачные копии и перенос средствами Android отключены. Удаление приложения или очистка его данных удаляет локальный дневник.

Через **⚙ → Резервная копия** можно сохранить JSON-файл в выбранное место. Файл не зашифрован. Если выбрать облачного поставщика в системном диалоге, файл сохранится у него по вашему выбору. Подробнее: [PRIVACY.md](PRIVACY.md).

Импорт поддерживает файлы до 16 МиБ и до 100 000 записей. Он проверяет формат и ссылки, добавляет отсутствующие записи по UUID, сохраняет существующие комментарии и восстанавливает набор кнопок из копии. Повторный импорт не создаёт дубликаты. Ошибка валидации или конфликт версии эмоции откатывает импорт целиком. При ошибке записи файла копия может остаться неполной; приложение сообщает о неудаче.

База SQLite автоматически мигрирует со схем 1/2 на схему 3. Версии эмоций неизменяемы. При повреждении базы отключено стандартное автоматическое удаление SQLite; приложение сохраняет файл и показывает ошибку вместо сброса дневника.

## Сборка

Нужны OpenJDK 17, Android SDK Platform 36 и Build Tools 35.0.0. Gradle Wrapper 8.11.1 включён в проект, дистрибутив проверяется SHA-256. AGP закреплён на 8.10.1. Для первой сборки нужен интернет для инструментов; самому приложению сеть не нужна.

```sh
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/android-sdk
sh gradlew --no-daemon assembleDebug assembleRelease bundleRelease lint
```

В Windows используйте `gradlew.bat` или:

```powershell
.\build.ps1 -SdkPath 'C:\path\to\Android\Sdk' -JavaPath 'C:\path\to\jdk17' -Release
```

Результаты находятся в `app/build/outputs/apk/` и `app/build/outputs/bundle/`. Без настроенной релизной подписи `assembleRelease` создаёт **неподписанный** APK; его нельзя установить до подписания. Ключи не включены в исходники.

Для подписи предоставьте через окружение `NINE_FEELINGS_KEYSTORE` и `NINE_FEELINGS_PASSWORD_FILE`. Alias ключа — `release`, пароль читается из отдельного локального файла. Храните ключ и пароль вне репозитория и сделайте их безопасную копию до публичного распространения.

Старые прототипы 0.1–0.3 подписаны тестовым ключом. Для локальной проверки совместимого обновления можно передать `-PcompatDebugKeystore=/path/to/old/debug.jks`. Это **не** ключ публичного релиза. Переход с прототипа на новую релизную подпись требует сначала экспортировать дневник, затем установить релиз и импортировать копию. Удалять старое приложение до создания копии нельзя. Сборки официального F-Droid по умолчанию также могут иметь другую подпись.

## Тесты

```sh
sh gradlew connectedDebugAndroidTest
```

Требуется запущенный эмулятор или подключённое тестовое устройство. Тесты создают отдельные базы с префиксом `test-`; личный дневник не используется. Проверяются миграции v1/v2, неизменность старых эмоций, SQL-статистика, пагинация, валидация и атомарность импорта, отсутствие дубликатов, отказ вывода копии, ограничение размера и сохранение повреждённой базы. Тестовые базы остаются в данных тестовой установки для диагностики.

CI настроен для Ubuntu и эмуляторов API 26/36. Результаты запусков доступны на вкладке Actions публичного репозитория.

## Чистая Linux-сборка

```sh
docker build -f packaging/Dockerfile -t nine-feelings-build .
docker run --rm -v "$PWD:/workspace" -w /workspace nine-feelings-build sh gradlew --no-daemon assembleRelease bundleRelease lint
```

Для проверки без локальных ключей и кеша используйте чистую копию исходников. Dockerfile закрепляет базовый образ по digest и проверяет архив Android CLI по SHA-256. Контейнер не является официальной средой F-Droid: окончательная сборка в их инфраструктуре проверяется отдельно.

## Исходники и F-Droid

XML-ресурсы включены в репозиторий. Node.js нужен только для изменения генератора: `node generate-resources.cjs`. Пользовательские данные, APK/AAB, ключи, кеши и SDK не входят в исходный архив.

В `packaging/fdroid.template.yml` подготовлен рецепт. URL репозитория и тег выпуска заполнены. Перед подачей нужно выполнить проверки `fdroid lint` / `fdroid build` в инфраструктуре F-Droid. Шаблон пока не подан на рассмотрение.
